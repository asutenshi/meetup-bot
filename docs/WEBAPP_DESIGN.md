## Выбранное направление — «Секции-карточки»

Из трёх проработанных вариантов (родные строки Telegram / секции-карточки /
плоский минимал) выбран **вариант B — «Секции-карточки»**.

Форма делится на смысловые блоки-карточки, у каждого — заголовок с иконкой:
«Когда», «Где», «О чём», «Деньги и места», «Кто организует». Внутри карточки —
поля с подписью сверху; необязательные поля помечены бейджем «необязательно».
Первичное действие («Опубликовать анонс») — кнопка в липком футере экрана.

Почему этот вариант: длинную форму проще просканировать глазами, бейджи
необязательности снимают вопросы, есть запас места под иконки и подсказки при
росте числа полей. Цена — своя небольшая компонентная библиотека поверх
`@telegram-apps/telegram-ui`, но она переиспользуется на 2.7 и 3.1.

- **Референс выбранного варианта** (в репозитории, открывается в браузере,
  внутри — переключатели темы и акцента):
  [`design/webapp-event-form.html`](./design/webapp-event-form.html).
- **Полное сравнение трёх вариантов** (артефакт-макет, для истории решения):
  <https://claude.ai/code/artifact/225afc17-b342-4dba-930f-224c3e05d758>.

## Раскладка

- Один экран, вертикальная прокрутка, поля сверху вниз в порядке из `TZ.md` §4.3.
- Шапка — заголовок Mini App (даёт Telegram), свой служебный подзаголовок
  опционален.
- Контент — колонка карточек: внешние отступы 14–16 px, зазор между карточками
  12–14 px.
- Карточка — скруглённый контейнер (radius 16) с тонкой рамкой и мягкой тенью,
  внутренний паддинг 16, поля внутри с зазором 14–15 px.
- Футер — липкий (`position: sticky; bottom: 0`) с градиентным затуханием к фону,
  внутри одна первичная кнопка на всю ширину (radius 12).
- Ширина резиновая, расчёт на телефон: тач-цели ≥ 44 px, поля ввода и
  кнопки — текст 16 px (мельче → iOS зумит экран на фокусе), подписи 13 px.

## Инвентарь компонентов

| Компонент | Назначение | Заметки |
|---|---|---|
| `ScreenHeader` | заголовок Mini App | предоставляет Telegram; свой подзаголовок опционален |
| `Card` | смысловой блок формы | заголовок + иконка 16–17 px цвета `--accent`, список полей |
| `Field` | обёртка «подпись + контрол» | подпись 13 px / 600, бейдж «необязательно» справа от подписи |
| `TextInput` / `TextArea` | строковые и многострочные поля | текст 16 px (без зума на фокусе в iOS), рамка `--border`, при фокусе — кольцо `--accent-soft` + `border-color: --accent` |
| `PickerRow` | дата, выбор из списка | строка: человекочитаемое значение слева, шеврон справа; пустое состояние — цвет `--tg-hint`. Для даты — своя строка по токенам поверх нативного `<input type="date">` (`opacity: 0`), календарь остаётся нативным ОС/браузера. `color-scheme` привязан к теме Telegram, чтобы виджет не был светлым на тёмном фоне |
| `TimeSelect` | время (часы : минуты) | два `<select>` — чч `00`–`23`, мм шаг 5. Не `<input type="time">` (тот рисует 12/24-часовой формат по локали браузера) и не часть `datetime-local` (на десктопе `showPicker()` открывает только календарь) |
| `PeopleList` | со-организаторы, выбор людей | строка: аватар-инициалы + имя + чекбокс-квадрат справа; отмеченный квадрат — заливка `--accent` |
| `OptionalBadge` | пометка необязательного поля | пилюля с рамкой `--tg-sep`, текст `--tg-hint` |
| `StickyFooter` + `PrimaryButton` | первичное действие экрана | кнопка на всю ширину, фон `--accent`, текст `--accent-contrast` |
| `Hint` | подсказка под полем или карточкой | 12 px, `--tg-hint` |

Аватар — круг с инициалами, по умолчанию фон `--accent-soft`, текст `--accent`
(пока нет настоящих фото).

## Токены

Компоненты не используют «сырые» цвета — только семантические токены (CSS custom
properties). Поверхности и текст берутся из Telegram `themeParams` (светлая и
тёмная темы приходят от клиента), фирменный акцент — наш.

| Токен | Роль | Источник |
|---|---|---|
| `--tg-bg` | фон экрана | `themeParams.secondary_bg_color` |
| `--tg-section` | фон карточки и поверхностей | `themeParams.section_bg_color` / `bg_color` |
| `--tg-text` | основной текст | `themeParams.text_color` |
| `--tg-hint` | подписи, подсказки, плейсхолдеры | `themeParams.hint_color` |
| `--tg-sep` | разделители и нейтральные рамки | `themeParams.section_separator_color` |
| `--border` | рамка полей ввода | производный от `--tg-sep` |
| `--radius-card` / `--radius-field` / `--radius-btn` | 16 / 10 / 12 px | константы |
| `--shadow-card` | тень карточки | константа, слабее в тёмной теме |
| `--accent` | **фирменный акцент** | **наш — см. следующий раздел** |
| `--accent-contrast` | текст и иконки на акценте | наш |
| `--accent-soft` | подложки, focus-ring, аватар | `color-mix(--accent, --tg-section)` |

## Акцентный цвет — не выбран, держим сменяемым

Финальный акцентный цвет пока **не определён**. Обязательное требование к каркасу
(`TASKS.md` 2.1) и ко всем экранам Web App:

- Акцент задаётся **одним местом** — токеном `--accent` (+ `--accent-contrast`).
  `--accent-soft` и прочие оттенки — производные через `color-mix()`, не
  отдельные константы.
- Ни один компонент не хардкодит акцентный цвет — только `var(--accent)` и
  производные. Смена бренд-цвета = правка одного объявления, без прохода по
  компонентам.
- Во фронтенде акцент вынесен в одну точку правки: константа/переменная в файле
  темы (или `:root`), из которой значение попадает в CSS-токен. Плюсом —
  возможность переопределить на этапе сборки (env-переменная), но минимум —
  одна строка в коде.
- Кандидаты, которые крутили на макете: нейтральный графит (текущая заглушка),
  Telegram-синий, индиго, зелёный, терракота, слива. Выбор зафиксируем отдельным
  решением и обновим этот раздел.

Критерий «сделано правильно»: поиск по фронтенду не находит акцентных hex-констант
вне определения токена/темы; смена одного значения перекрашивает все экраны.

## Темы

- Светлая и тёмная — обе обязательны, значения из `themeParams`, вручную не
  инвертируем.
- Тень карточки и подложки — слабее в тёмной теме.
- Акцент должен оставаться читаемым на обоих фонах — учесть при финальном выборе
  цвета.
